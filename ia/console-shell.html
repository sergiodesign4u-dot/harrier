01 · Purpose

Why a frame is a node

Split pane review was chosen at stage 01 for three reasons, and the second is structural: cheap override needs the list to survive the decision. If the case takes the whole window, rejecting Clerk costs a navigation back, and design principle 3 says override is one key.

So the shell exists to make one guarantee: the list is never lost. Everything else it holds is here because it has to be true on every screen rather than on one. Nobody opens the shell. It serves the main job structurally rather than directly.

05 · Keyboard

Specification, not enhancement

The list pane is a grid in the ARIA sense rather than a list of links. The W3C Authoring Practices define the model: "A grid is a composite widget so it: Always contains multiple focusable elements. Only one of the focusable elements contained by the grid is included in the page tab sequence. Requires the author to provide code that manages focus movement inside it."

KeyDoesSource
TabMoves between zones. One stop for the whole listAPG grid, single tab stop

Home, EndFirst and last row in viewAPG, adapted to whole-row selection
Ctrl + Home, EndFirst and last row of the listAPG: "Control + Home: moves focus to the first cell in the first row"

EscapeDeselects, returns Z5 to the fleetProduct. This is the way back to 3.5, and the discoverability risk the base layer named

Verdict keys are not defined here. Accept, amend and reject belong to 4.1, because a key that files a verdict must not exist on a screen with no verdict to file.

Pointer targets. WCAG 2.2 SC 2.5.8 Target Size (Minimum), Level AA: "The size of the target for pointer inputs is at least 24 by 24 CSS pixels". Every control in the shell meets it. The stronger 44 by 44 figure often quoted belongs to a different criterion, which was not opened in this session, so it stands as [?] rather than as a requirement.

The slot a public product spends on SEO

/clients7.1LATER

Indexing. Every route above is noindex, no schema, no sitemap entry. The only crawlable URL in the product is 1.1 sign in. Stated once here and inherited, rather than repeated on forty two nodes.

Heading hierarchy. The shell carries no h1. The h1 belongs to whatever fills Z4 plus Z5, so a case open in the pane makes the case the heading of the page. Identity for assistive technology rather than for search.

Permission. The analyst sees the tenants their provider scope covers and nothing else. A route naming a tenant outside that scope renders 8.3 rather than an empty result, because tenant data isolation is a stated requirement and an empty result is indistinguishable from a quiet client.

What the log records. Every render of 4.1 and every verdict action carries the analyst identity and the shift from Z1. That is why Z1 never scrolls away: it is not decoration, it is the subject of the audit record.
