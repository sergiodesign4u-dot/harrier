01 · Purpose

Why a frame is a node

Split pane review was chosen at stage 01 for three reasons, and the second is structural: cheap override needs the list to survive the decision. If the case takes the whole window, rejecting Clerk costs a navigation back, and design principle 3 says override is one key.

So the shell exists to make one guarantee: the list is never lost. Everything else it holds is here because it has to be true on every screen rather than on one. Nobody opens the shell. It serves the main job structurally rather than directly.

05 · Keyboard

Specification, not enhancement

The list pane is a grid in the ARIA sense rather than a list of links. The W3C Authoring Practices define the model: "A grid is a composite widget so it: Always contains multiple focusable elements. Only one of the focusable elements contained by the grid is included in the page tab sequence. Requires the author to provide code that manages focus movement inside it."

Verdict keys are not defined here. Accept, amend and reject belong to 4.1, because a key that files a verdict must not exist on a screen with no verdict to file.

Corrected a fourth time at the stage 08 audit, and this time it was the drawing

The prose of this node had been corrected three times by the nodes it contains. The wireframe never was, and a reader preparing stage 04 found four places where the frame disagreed with its own contents: the top bar drew four navigation items where 0.2 settled on three, the pane header carried verdict controls that 4.1 puts in the foot, the 360 frame omitted Z2 which 0.4 requires in the same place, and the annunciator used a level name that 0.6 has since replaced.

All four are fixed above. The rule this produced: a container node is redrawn whenever a node inside it settles something, prose and drawing together. Prose alone is how a frame goes stale while reading as current.

And they are live only while a case has focus. That is not a refinement, it is how this product satisfies WCAG SC 2.1.4 Character Key Shortcuts, Level A. The reasoning and the remap mechanism are on 0.5.

Pointer targets. WCAG 2.2 SC 2.5.8 Target Size (Minimum), Level AA: "The size of the target for pointer inputs is at least 24 by 24 CSS pixels". Every control in the shell meets it. The stronger 44 by 44 figure often quoted belongs to a different criterion, which was not opened in this session, so it stands as [?] rather than as a requirement.

Indexing. Every route above is noindex, no schema, no sitemap entry. The only crawlable URL in the product is 1.1 sign in. Stated once here and inherited, rather than repeated on forty two nodes.

Heading hierarchy. The shell carries no h1. The h1 belongs to whatever fills Z4 plus Z5, so a case open in the pane makes the case the heading of the page. Identity for assistive technology rather than for search.

Permission. The analyst sees the tenants their provider scope covers and nothing else. A route naming a tenant outside that scope renders 8.1, identically to a case that does not exist.

Corrected at the stage 08 audit, and the earlier reasoning was backwards

This node originally said 8.3, arguing that an empty result is indistinguishable from a quiet client. That is true, and it is the smaller risk: she already knows which tenants she covers, and 3.6 never offers one she does not. The larger risk runs the other way. If out of scope renders differently from not found, the address bar distinguishes "this client exists and is somebody's" from "no such client", which is a disclosure across providers.

Inside her scope, an empty result may name the tenant. Outside it, everything is 8.1.

What the log records. Every render of 4.1 and every verdict action carries the analyst identity and the shift from Z1. That is why Z1 never scrolls away: it is not decoration, it is the subject of the audit record.

  1. Is the split resizable, and is that position remembered per analyst? Answered, and the answer is yes. Closed at step 4 of the block bank: the PagerDuty Operations Console documentation, opened live, states that the side panel width is changed by dragging and that "PagerDuty will remember your settings for later visits." A shipped console in this exact category does both, so this is a requirement rather than an open question, and it does not travel to stage 04.
  2. What does Z5 hold on /shift? The brief does not hold the split. Either the shell has a no split mode, which weakens the guarantee in section 1, or 2.1 sits outside the shell entirely. Named here rather than settled, because the answer is a drawing decision.
  3. Does a second analyst picking up a case change the row for the first? The console is multi analyst by premise, but no flow covers a collision. If yes, it is a state that does not exist on the map yet.
