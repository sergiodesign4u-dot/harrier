Checks

The instruments

Twelve of them, in design/kit/checks/, and each one exists because a class of defect got through everything else. They all drive a real browser, because every defect they were written for has the same shape: the value is never wrong in any file, and it resolves wrong. A reader sees correct text, a search sees a correct declaration, and only a rendering sees what happened.

There are no screenshots in this system, and these are why. A picture of a component is a second copy: it has to be retaken, it goes stale without saying so, and the first one taken on this stand documented a focus ring it did not contain, because a focus set from a script does not match :focus-visible. What the refactors of stage 08 and 09 promise is proved by rendering the tree twice and comparing it element by element, which says which element moved rather than how many pixels changed.

What each one finds, and what it says today

contrast.mjsstage 07

A contrast ratio for every text node on every page, in both themes and at both viewports, with the ground composited layer by layer down to the body. Reading the first three numbers of an rgba() and calling it solid reports a panel item at 3.58 that is really 4.87, which is a false failure and can as easily be a false pass.

It found the defect that no reader, no search and no reviewer can see. At stage 06, a light documentation palette inherited by two dark pages, where the opening paragraph ran at 1.42:1 and every file path at 1.14:1 for two stages. At stage 07, 1018 failures on 128 pages made by four values. At stage 08, a stand class repainting the first product component placed inside it. At stage 09, a grid track sized by its content pushing a page sideways at 1440.

rules.mjsstage 09

The eleven usage rules, as functions. A prohibition written only in prose is a prohibition nobody runs. Each rule is measured at both viewports on what renders rather than on what is in the markup, and each may answer "not applicable": a screen with no dialog does not pass the dialog rule, it is not asked. Counting those as passes is how a suite reports green while testing nothing.

Two of the eleven only became correct when they stopped reading the file and started reading the box. Two primary actions in a document are one primary action on a screen when the second is the viewport twin of the first. And an overlay pinned to the viewport covers a pane that sits below the fold, because the pane passes under it the moment anybody scrolls.

1 broken, and it is R11 on 16 screens

refactor.mjsstage 09

The tree as it stood before the first edit against the tree as it stands now, walked element by element in document order at both viewports. The baseline is a copy of design/ taken outside the repository, so no image and no duplicate tree is committed.

It reports the tree shape before the boxes. A pattern class is added to an element that already exists, so the two subtrees must have the same element count in the same order, and a count that does not line up is a bigger finding than any box that moved.

compose.mjsstage 09

Every composition in the grey corpus, counted as host{child child} with runs of the same child collapsed, so a queue of eighteen rows and a queue of three are one composition. It reads the DOM and not the file, because two of the corpus's biggest compositions live in no html file at all: the whole global navigation and both shell zones are written by a script at load.

The same pass read backwards gives the prohibitions: for every class, the maximum instances found on any one screen. A maximum of one is a candidate for a rule and never the rule itself, because the counter cannot tell a deliberate constraint from a component that has not yet had a second reason.

coverage.mjsstage 08

Every selector of the deleted kit.css, against every selector the system declares, through a map of what was renamed and a list of what was deliberately dropped with its reason. It is what made deleting a 367 selector stylesheet a measurement rather than a hope.

Its own failure mode is a row that can never fire, and stage 09 found one: an earlier rename rewrote the prefix a later row was matching on, so the row sat there looking like cover. A declared list with nothing in it fails this system's rules as loudly as an undeclared case.

geometry.mjsstage 08

The box of each component on its own stand page against the same component on the screen it stands on. It exists because the stand can drift from the product silently: the page looks like documentation and the screen looks like a screen, and nobody compares them.

It was written after a font shorthand quietly reset a line height and moved every chip by 4.94px, and then it found the product's own defect: three chip heights in one scope bar, because the element was deciding the height.

themes.mjsstage 08

The dark theme as a stress test of the neighbourhood rather than of a component: fills that merge, two roles that arrive at one value, a role that clears its threshold in one theme and fails in the other, and a pair that looks copied rather than measured.

It printed FAIL fifteen times on its first run and meant nothing. It assumed a token resolves to rgb() and they resolve to hex, so every ratio was NaN. An instrument that has never been wrong out loud is an instrument nobody has checked.

migrate.mjsstage 08

The migrated screen against the version in the last commit, element by element. It is the instrument that sees a cascade defect, where both stylesheets are correct, both declarations are correct, and what is wrong is which of them wins. It found three: a component beating a viewport utility because the system loads later, a media query written where a class selector belonged, and a narrow only rule hoisted to the top level.

pixels.mjs and attribute.mjsstage 08

A per pixel difference computed in a browser canvas, and a check that every visible difference is attributable to a named row of docs/tokens-audit.md. They answer how much and where, where the two comparisons above answer which element, and the pair is what makes "we did change some things" stop eating the whole comparison.

syntax.mjsstage 09

Two counts and nothing else: comment openers against terminators, and braces. The cheapest instrument here and the last one written, because it took a self inflicted wound to see the need for it.

An edit to a comment in tokens.css dropped its terminator. The comment swallowed two declarations and the closing brace of the semantic block, so everything after it became nested inside that block, and two media queries then read :root as a descendant of the root, which nothing can be. Both of the system's responsive primitives went dead: the pane stopped narrowing below 1560 and the queue row stopped collapsing to one column at 360.

Every other instrument on this page passed while it was broken. The contrast sweep, because nothing about colour changed. The overflow check, because a row that is suddenly 646px wide sits inside a scroll container and clips. The usage rules, because none of the eleven is about a track. The baseline comparison, because it hides the panel and reads the product's boxes, and at 1440 they were unchanged.

The rule they were all written under

An instrument that has never found anything is not a clean result. It is an untested instrument.

That sentence is in CLAUDE.md because it was paid for: a search meant to catch a rule declared twice compared inline against inline and never inline against the shared sheet, and reported clean for two steps while ten rules were duplicated. Every instrument here has a paragraph in its own header naming the defect it failed to catch on its first run, and three of them were corrected during stage 09 alone: one counted a contents page as a screen, one measured a rule other than the one it was named after, and one compared two rectangles at a scroll position instead of across a column. The twelfth exists because a defect got past all eleven.

The full log of what each pass found, what was fixed, and what was withdrawn on verification is the critique log. What the system knows it does not do yet is the backlog, and every row of it names who closes it.
